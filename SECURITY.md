# Security

Do not report suspected vulnerabilities in public issues when they contain secrets, private data, or exploitable details.

Open a private security report through the repository's configured GitHub security contact or maintainer contact. Include affected version, runtime/client context, reproducible steps, impact, and a minimal safe reproduction. Do not include credentials, API keys, customer data, or full private request payloads.

For ordinary bugs without sensitive security impact, use a public issue with an anonymized reproduction and the relevant runtime and client versions.
